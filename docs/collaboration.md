## 两人分工与协作

<a id="s13-1"></a>

### 开工约定与单一负责人

**A 负责后台、AI 与集成；B 负责视频渲染与前端。** 首次开工把 A、B 对应到具体人名。以下只覆盖 MVP，V2/V3 在 MVP 验收后另排。用文件归属减少冲突，用接口样例和开发替身减少等待；真实端到端验收仍需双方共同完成。

| 文件 / 范围 | 唯一主负责人 | 对方如何参与 |
| --- | --- | --- |
| `api/main.py`、`api/jobs.py`、HTTP 错误处理、播放/下载路由 | A | B 按 OpenAPI 接页面，提出字段需求 |
| `core/ingest.py`、`core/storage.py`、项目/素材/版本记录 | A | B 使用登记后的资源；上传、元数据、缩略图生成和 ID 统一由 A 管理 |
| `core/analyze.py`、`director.py`、`intent.py`、AI 测试 | A | B 参与观看与人工标注，不改模型适配器 |
| `core/timeline.py`、`pipeline.py`、`music.py`、设置合并 | A | B 提供真实渲染约束与标题布局函数；A 为选定 BGM 生成节拍数据 |
| `core/render.py`、`core/titlecard.py`、渲染命令行入口 | B | A 仅通过[Python 模块交接：A 调度，B 渲染](reference/api.md#s10-6)调用，不直接改 FFmpeg 滤镜实现 |
| `frontend/**`、前端依赖与锁文件 | B | A 按接口定义提供服务，不直接重写页面组件 |
| `style/presets/**`、字体/BGM/装饰文件、视觉样片 | B | A 消费固定预设；B 先确定一首曲目和稳定资源 ID，不中途替换同名文件 |
| `core/schemas.py`、`style/style_schema.py`、`contracts/**` | A | 对外契约修改双方确认；B 不另建冲突的字段定义 |
| Python 依赖清单、`.replit`、`.env.example`、存储配置 | A | B 报告所需 FFmpeg、字体和 Python 库版本，由 A 统一合并 |
| 根 README、集成检查、正式部署、版本标签 | A | B 补充自己负责模块的说明和验收证据 |

这里把旧分工中 B 的 `ingest` 职责移到 A，避免上传 API、素材登记和持久保存分别由两个人写。B 先做渲染最短路径，再完成页面；视觉打磨排在真实闭环之后。若一方负荷明显过重，可以转交一个尚未开始的文件范围，先更新归属，再由接手人修改，不同时编辑同一文件。

<a id="s13-2"></a>

### 开工第一小时的共同底稿

前 15 分钟共同完成：指定 A/B、建立一个 GitHub 仓库、确认 `contracts/` 契约版本、确认[前后端怎么交互：从一次点击开始](reference/api.md#s10)接口、准备共享小样文件。后续各自在自己的分支创建骨架，第一小时内交出以下内容：

- A：后端 `/api/health` 能启动；记录 API 地址、运行方式与环境变量；采用已有接口定义和样例，不等待 AI 选型。
- B：前端空页面可以启动和构建，`/api` 代理可连接随附 mock；本地渲染命令行入口至少能读取九秒时间线和素材路径映射。
- 共同：确定同一套 Node、Python、包管理器与依赖版本，写入版本文件/锁文件和 README；记录共享素材的 ID、文件散列、时长与方向，不靠各自随手选的视频联调。

原有秒/帧、ID、版本和 MVP 能力约定直接沿用[JSON 数据契约：MVP 可用，V2/V3 可扩展](reference/timeline.md#s6)，不重新发明。`api.openapi.json` 是 HTTP 结构依据，`contracts.schema.json` 是项目/剪辑数据结构依据；语义与阶段限制按文档执行。OpenAPI 内复制的 `Data_*` 定义应与后者一致，随附检查会核对，改变时一起更新。

### 并行任务和交接节点

| 时段 | A 可独立完成 | B 可独立完成 | 当次必须交接什么 |
| --- | --- | --- | --- |
| 0–1 小时 | 仓库、API 骨架、配置与契约；启动 mock/替身检查 | 前端骨架、共享素材准备、渲染入口 | 接口版本、启动方式、真实素材清单、文件负责人 |
| 1–2 小时 | 真实上传/登记、本地 storage、Replit 最小发布与健康检查 | 本地三段硬切、BGM、字体/标题小样；页面连接 mock | A 的真实上传响应；B 的真实小 MP4、FFmpeg/字体依赖与启动命令 |
| 2–4 小时 | 用 RenderStub 测队列、错误、幂等、项目恢复和版本；接 App Storage | 实现真实 Renderer、标题布局和进度回调；用 mock 做上传/处理中/失败/完成页面 | 同签名真实渲染器；项目/任务接口能按样例响应。B 优先交渲染，再打磨页面 |
| 4–6 小时 | 切换到 B 的真实渲染器，修后端与部署问题 | 切换到 A 的真实 API，修渲染和页面问题 | Replit A/B/C 关卡通过，含实际负载和恢复测试；mock 结果不计入 |
| 6–7 小时 | 按[AI 素材理解与选片测试：第 6–7 小时首测，第 14 小时前验证成片](ai-selection.md#s20-4)测 AI 理解/选片 | 继续用固定时间线完善视觉，复核字体和布局 | 模型输入与输出实测记录；无需等 AI 才能改视觉 |
| 7–14 小时 | 接通 AI→计划→时间线；检查关键瞬间 | 用真实时间线复核成片，完成网页四种状态 | 真正自动生成约 30 秒速剪，时间线无需人工改字段 |
| 14–24 小时 | 三类修改、歧义处理、幂等、失败恢复、撤销 | 修改/选择/撤销 UI，调色与标题响应，第二套素材视觉检查 | MVP 所有验收通过，稳定提交已保留 |
| 24–36 小时 | 仅按已有阶段关卡安排 V2、冻结和提交材料 | 同左；B 负责操作演示和成片备份 | A 讲产品与 AI，B 操作；完整彩排和备份 |

这是并行工作安排，不是保证工时；若第 4 小时还不能相互替换真实实现，就把剩余时间集中到缺口，不继续叠加页面装饰或模型候选。

### 被依赖项拖住时，按固定方式继续

| 缺的东西 | 可以继续做什么 | 什么不能算完成 |
| --- | --- | --- |
| A 的 API 未就绪 | B 用 `mock_api.py` 开发页面、错误提示、版本与待选择状态 | 真实上传、后端恢复与线上验收 |
| B 的渲染器未就绪 | A 注入 `RenderStub` 成功/失败模式，测试队列、存储调用、版本逻辑；测试目录与真实项目分开 | 真实出片、视频格式/画质、渲染性能 |
| AI 未就绪 | A 用手工计划走编译，B 用同一时间线做渲染和视觉 | AI 内容理解与选片测试 |
| 字体测量未就绪 | A 使用固定标题 fixture 测流水线，B 独立实现 `layout_title` | 动态标题和溢出处理 |
| Replit 发布暂时阻塞 | A 处理部署；B 继续本地真实渲染和 mock 页面 | Replit 正式环境验证，不把本地结果记为线上通过 |

双方优先交“对方要调用的函数或接口”，再完成自己模块的全部功能。阻塞超过 30 分钟，提交一个可复现输入、原始错误和最小失败命令到仓库 issue 或协作文档，由对应负责人处理；调用方继续用约定替身，不私自绕过契约。需要修改其他人的文件时先同步归属，不能让两个编码助手同时重写。

### 合并、契约变更和发布纪律

- 每个人使用独立本地工作目录/分支，例如 `feat/backend-core` 和 `feat/render-ui`。Replit Agent 的改动也使用单独分支，并明确属于 A 还是 B 的文件范围。
- A 负责集成到 `main` 和正式发布；`main` 保持能运行。每 2–3 小时做一次小合并并联调，不能直到最后才一次性合并两个大分支。
- 公共契约需要改变时，先给出新旧请求/响应或函数签名差异，双方确认，再一次更新 schema、样例、替身和两侧调用代码。由 A 合并成一个完整变更，不先上线一边。修改字段含义时升级对应版本，不能静默兼容猜测。
- 遇到依赖或锁文件冲突，由该文件负责人重新生成并验证，不以整份“保留我的版本”覆盖。两人准备修改同一个文件时，先划定谁提交这次改动。
- 合并前至少通过契约样例检查和自己模块检查；到第 4 小时起，合并涉及主链路的修改后，用同一套三段真实素材跑一次上传到播放。mock 检查通过与真实闭环通过分别记录。
- Replit 发布使用已合并的 `main`，记录提交 ID 和部署配置；发布后验证健康检查与一段真实出片。线上发现问题优先恢复上一已验证提交，再修复重发，不在演示版本上临时叠改。

<a id="s13-6"></a>

### 启动、配置与完成定义

仓库使用 `frontend/`、`api/`、`core/`、`contracts/`、`fixtures/` 和 `work/` 结构。代码、字段、注释和提交说明用英文，项目说明可以用中文。开发端口约定为前端 5173、API 8000，前端只调用相对 `/api`；Replit 对外端口以实际配置为准，由 A 映射。

随附工具现在即可运行，命令见 [协作包使用说明](../contracts/collaboration/README.md)。应用仓库第一小时需要补齐实际前后端启动脚本；下列真实应用命令是待实现的统一约定，不表示应用已存在：

```text
前端：npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173
后端：python3 -m uvicorn api.main:app --host 127.0.0.1 --port 8000 --workers 1
构建：npm --prefix frontend run build
渲染：python3 tools/render_fixture.py --timeline contracts/collaboration/smoke9.timeline.json --asset-map fixtures/local-paths.json --output work/smoke9.mp4
```

渲染 CLI 由 B 提供；文件映射由 A/B 首小时共同核对，B 可先在本地使用。运行期间不要对后台任务使用自动重载来做持续性验收；代码热重载导致的任务中断要明确区分。

`.env.example` 只提交变量名和非秘密默认值。A 统一管理 `APP_ENV`、`API_PORT`、`WORK_ROOT`、`STORAGE_BACKEND`、`AI_MODE`、`RENDER_MODE`、`AI_PROVIDER`、`AI_MODEL`、所选供应商密钥变量、`MAX_FILE_BYTES`、`MAX_PROJECT_BYTES`、`JOB_TIMEOUT_SECONDS`；B 不自建另一套同义命名。开发初始体积限制为单文件 100 MiB、项目 500 MiB，仍限制 15 段/180 秒，Replit 实测后收紧或调整，并通过 `/api/health` 下发实际值。前端不硬编码另一套上限。

mock 和 RenderStub 仅用于本地开发/测试，不配置到公开演示应用。前端看到 `simulation=true` 必须显示提示；正式发布启动时拒绝 mock 传输层或 stub 渲染器。环境验证阶段允许明确标记的手工计划加真实渲染，不冒充 AI 已接入。私人视频、大文件、密钥、缓存与生成结果不提交 Git；共享测试素材通过约定位置获取，用清单和散列保证两人使用相同文件。

一个模块交付时必须同时提供：代码提交、契约版本、启动或调用方式、一份可复现输入、实际输出或错误、当前限制。对方能直接调用才算交接完成；“我本地能跑”但需另一人改字段、猜路径或手动补状态，仍属于未完成联调。

## 36 小时时间表与阶段关卡

36 小时是比赛窗口，不等于每人连续工作 36 小时。MVP 是唯一必须交付的阶段；V2 是可选增量，V3 不纳入比赛交付承诺。

| 时间 | 目标 | 放行标准 |
| --- | --- | --- |
| 0–2 小时 | 首小时建立协作骨架，随后完成 Replit 环境预检（[两人分工与协作](collaboration.md#s13)、[开工验证：先确认 Replit 能跑通，再接 AI](deployment.md#s18-2)关卡 A） | 代码同步、依赖、字体、实际小视频合成通过；确认部署资源和费用，正式链接的健康检查可访问 |
| 2–6 小时 | Replit 正式环境闭环与实际负载（关卡 B、C） | 三段素材从上传到播放下载通过，关闭页面后任务继续、重启后成功版本可恢复；再用 10–15 段素材完成三次真实渲染并记录耗时与资源，不依赖 AI |
| 6–7 小时 | AI 素材理解与选片首轮测试（[AI 素材理解与选片测试：第 6–7 小时首测，第 14 小时前验证成片](ai-selection.md#s20-4)） | Replit A、B、C 通过后，用 10 段带人工标注的校园素材，检查关键瞬间、重复、误判、时间范围、耗时和用量；先测一家，最多比较另一家，首轮控制在一小时 |
| 7–14 小时 | 接通 AI 到真实速剪并复核 | 锁定可用主模型和抽帧配置，真实素材 → AI 选片排序 → 编译时间线 → 约 30 秒速剪；最终 MP4 中仍保留标注瞬间，具备固定标题与调色 |
| 14–24 小时 | 完成并验收整个 MVP | 三类修改、撤销、失败保留旧版、第二套素材、正式环境恢复和下载全部通过 |
| 24–30 小时 | 根据 MVP 状态决定 | 未通过就继续修 MVP；已通过才依序做 V2-1、V2-2、V2-3，能完成几项算几项 |
| 30–36 小时 | 冻结、彩排和提交 | 只修问题、录屏、备份、整理材料，不再新增功能 |

并行任务、独立开发入口和第 4 小时切换真实实现的交接点见[并行任务和交接节点](collaboration.md#s13-3)；本表用于整体放行。

**关卡失败时的处理：**

- 第 2 小时环境预检未通过：优先处理依赖、启动命令、端口或账号部署条件，保存具体错误，避免继续叠加功能。
- 第 6 小时 Replit 关卡 B、C 未通过：暂停 AI 接入和额外视觉效果开发，按[开工验证：先确认 Replit 能跑通，再接 AI](deployment.md#s18-2)定位。只有本地或 Preview 成片、只有九秒小样成功，都不能算线上验证完成。
- 第 7 小时首轮 AI 测试未通过：记录属于采样遗漏、理解错误、时间范围错误还是接口问题；按[AI 素材理解与选片测试：第 6–7 小时首测，第 14 小时前验证成片](ai-selection.md#s20-4)做针对性修复，继续使用 7–14 小时主链路预算，不展开更多模型比较。仍未达标就保持“未通过”，不以手工指定答案替代 AI 验收。
- 第 14 小时没有自动成片：暂停装饰打磨，完成真实 AI 到渲染链路。规则拼接只能作为明确标记的应急结果，不能算 AI 功能验收通过。
- 第 24 小时 MVP 未通过：取消比赛内的全部 V2/V3；剩余时间只修主流程并准备诚实展示当前能力的备份方案。
- 进入 V2 后某项影响稳定性：停用该项，恢复已保留的 MVP 或上一成功增量；不拖累比赛演示。
- 第 30 小时冻结：未验收功能从页面隐藏，不为了赶进度把半成品入口留给评委。

完成 MVP 本身就是可交付成果。不要为了达到某个阶段名称，同时开几条未完成的功能线。

## 编码助手如何参与

人的 A/B 分工保持不变，编码助手只领取其中明确的任务范围。每位成员可以自行选择工具、角色模板和本地调度方式；遵守 [共享项目规范](../AGENTS.md)、公共契约和文件归属即可，不要求队友安装同一套个人 agent 配置。当前任务见 [进度表](status.md)。集成分支为共享仓库的 `main`，由 A 负责合并。
