# 哪些文档需要一直保留

[返回总览](../README.md)。团队共享的当前文档与契约随代码放在同一个 Git 仓库；个人开发配置留在本地。**保留不等于每次都读，也不等于每轮都更新。**

## 你平时重点看的三份

| 文件 | 用途 | 更新时机 |
| --- | --- | --- |
| [README](../README.md) | 项目介绍和入口导航 | 产品概况、入口或真实启动方式改变 |
| [协作手册](collaboration.md) | 谁负责什么、何时交接、怎样避免等待 | 分工、接口交接或里程碑改变 |
| [当前进度](status.md) | 已完成、阻塞、接下来做什么 | 有实际进展或需要决定时，由 A 汇总更新 |

你作出的重要产品/技术决定，还应保存到 [decisions.md](decisions.md)；agent 会据此避免重复讨论和恢复旧方案。

## 仓库中长期保留的内容

| 内容 | 为什么保留 | 主要维护者 |
| --- | --- | --- |
| [AGENTS.md](../AGENTS.md) | agent 的简短规则与阅读路由 | A |
| [产品定义](product.md)、[MVP 对照](mvp-coverage.md) | 比赛目标、当前实现与缺口 | 两人确认范围，A 维护 |
| [架构](architecture.md)、[契约导航](contracts.md)、[技术参考](reference/) | 防止模块和字段各自演化 | A；涉及 B 的边界共同核对 |
| [contracts/](../contracts/) | 机器可验证 schema、样例、API 和开发替身 | A；公共变更两边同步 |
| [视觉规范](visual-design.md) | 页面与成片的统一风格 | B 管页面，A 管视频标题/成片；共同核对 |
| [验收](acceptance.md)、[部署](deployment.md)、[AI 测试](ai-selection.md) | 明确什么才算可演示、真实有效 | 模块负责人提供证据，A更新状态 |
| [决策记录](decisions.md)、[进度表](status.md) | 跨会话、跨电脑恢复工作 | A 统一维护 |
| [Demo 准备](demo.md) | 素材许可、录屏、提交和彩排 | A/B |

共享仓库必须保留的是团队当前文档和契约；你只需频繁关注上面的三份，以及需要你决定的事项。文档要与代码一起提交和同步，不能只留在某个聊天附件里。

## 归档和临时材料

- `docs/archive/`：旧长文档只留本地回溯，已忽略，不上传 GitHub。
- `agent-roles/`、`docs/agent-workflow.md`、`.codex/`、`.agents/`、`LOCAL-DEVELOPMENT.md`：个人编码助手的角色/调度/设置，留在本地。队友无需安装相同配置。
- `AGENTS.md`：名称含 agent，但内容是团队共享规范和文档导航，应随仓库同步，不包含个人模型或调度设置。
- `work/`：草稿、迁移脚本、临时日志和缓存；确认重要结论已保存后可清理，不作为唯一验收依据。
- `outputs/`：本次可分享的文档包和说明；只是快照，后续以仓库当前文件为准，避免拿旧压缩包覆盖新代码。
- 原素材、生成 MP4、私人标注与密钥：保留在约定的本地/云端位置；Git 保存必要清单、散列、许可和非敏感证据，不直接上传私人素材或密钥。

## 文档同步约定

每个要求只在一处详细定义，其他文档提供摘要和链接。字段以 schema/OpenAPI 为结构依据，跨字段语义以相应技术参考为依据，阶段范围以产品定义为依据；发现冲突先明确修正，不能自行删掉要求。

修改行为时顺手更新所属文档；完成/阻塞时更新进度；改变已确认方向时记录决定。结束任务前保留实际命令、结果、基线和未验项，不需要把聊天全文复制进仓库。
