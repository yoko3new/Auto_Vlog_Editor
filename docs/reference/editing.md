# 风格、编辑与版本规则

[返回项目总览](../../README.md)

何时读：修改风格、标题、暖度、删除、缓存或撤销时读。网页视觉另见 visual-design.md。

<a id="s7"></a>

## 风格配置与项目设置

<a id="s7-1"></a>

### 两类数据的区别

风格回答“长什么样”：字体、色彩、调色、转场、镜头节奏。

项目设置回答“这次要做什么”：画幅、时长、标题文案、是否保留原声和字幕。

读取带版本的风格预设 → 应用情绪预设 → 应用用户标题/暖度覆盖 → 按输出规格计算布局 → 保存 `config.settings` 和 `timeline.style_snapshot`。切换情绪/风格时如何清理旧覆盖见[`edit_request.json`：修改是受控操作，不是任意 JSON 补丁](timeline.md#s6-8)；渲染只读最终时间线，不重新加载默认预设。

<a id="s7-2"></a>

### 风格 schema

| 字段 | 内容 | MVP 实际支持与后续阶段 |
| --- | --- | --- |
| `id`、`display_name`、`description` | 风格标识与说明 | 保留 |
| `grade` | LUT、饱和度、对比度、亮度、暖度 | 先实现少量明确映射到滤镜的参数 |
| `title_card` | 文字、背景、时长、装饰、动画 | MVP 固定排版 + 静态装饰；V3-3 加动画 |
| `chapter_labels` | 活动标签、位置、动画 | V3-3 再实现；MVP 不显示 |
| `transitions` | 段内、段间转场与时长 | MVP 只有硬切；V3-3 再实现溶解 |
| `pacing` | 允许镜头时长、节拍选择、曲风 | 在允许时长内选择节拍切点 |

原草案中的拼贴、打字机、缩放、推镜等选项，只有渲染器实现并测试过才出现在可用 schema 中。不能出现“AI 可以选，但渲染器不会画”的合法配置。

原有 `cut_on=beat` 应明确解释为“切点落在节拍上”，不是“每个节拍都切”。`downbeat` 需要曲目提供对应标记；没有标记就不开放。

`TextStyle` 可保留字体、字号比例、大小写、字距、颜色和透明度。字距不是所有文字渲染方式都同样容易实现，第一版应先验证所选方案；未实现时使用固定值。

<a id="s7-3"></a>

### 设计约束

- 主标题最大，三层排版具有明确层次。
- 花体不使用全大写；短副标题才使用花体。
- 字体、LUT 和装饰只能来自本地已验证资源。
- 点缀色可来自素材，但标题必须可读；必要时加底色或阴影。
- `three_tier` 要求三层都有内容；装饰关闭时数量为零。
- 限制文案长度、行数和最小字号，处理超长标题。

Schema 负责结构，标题实际是否清楚仍要在视频尺寸下观看验证。

<a id="s7-4"></a>

### 项目设置的正式字段

这里引用[`config.json`：保存用户意图和版本设置](timeline.md#s6-4)的 `config.settings`，不再另建一套同义字段。

| 字段 | MVP 默认 | 后续阶段 |
| --- | --- | --- |
| `output` | 1280×720、30 fps、固定 MP4 编码档 | V3-1 切换 720×1280 |
| `duration_policy` | target、30 秒、容差 30 帧 | 删除时 natural；V2-2 加 20 秒；V3-2 加 60 秒 |
| `style_id` / `style_revision` | magazine_scrapbook / 1 | 只选登记且已实现的预设版本 |
| `title_overrides` | `{}` | 用户指定标题保存在对应层，不被重新选片覆盖 |
| `warmth_override` | null | 用户显式设置时保存绝对值 −1…1 |
| `mood_id` / `music_asset_id` | null / 固定音乐 ID | V2-1 开放情绪对应曲目 |
| `voice_enabled` / `subtitles_enabled` | false / false | V2-3 开放 |
| `excluded_clip_ids` | `[]` | 删除素材后持续保留，撤销则恢复旧版本的列表 |
| `creation_brief` | 无文字/参考图 | V3-5 输入，最终映射到已有参数 |

<a id="s8"></a>

## 预设风格

MVP 固定使用 `magazine_scrapbook` 基础版。V2-1 在同一布局上提供两种情绪参数；第二套完整布局 `clean_magazine` 属于 V3-3。

| | `magazine_scrapbook` | `clean_magazine` |
| --- | --- | --- |
| 状态 | MVP 基础版；V3-3 扩展动画 | V3-3 完整第二风格 |
| 气质 | 温暖、杂志排版、少量手账装饰 | 克制、留白、纯排版 |
| 调色 | 微暖、柔和，LUT 强度经真实素材验证 | 中性、略低饱和度 |
| 眉标 | DM Sans 或 Inter，短句、全大写 | 同左 |
| 主标题 | Playfair Display | Cormorant Garamond |
| 副标题 | Pinyon Script，内容保持简短 | 可先复用现有副标题实现 |
| 背景 | 第一段主画面 | 先复用单画面；双画面拼贴后置 |
| 装饰 | 0–2 个固定纸张、胶带或线条元素 | 无 |
| 章节标签（V3-3） | 活动短语，例如 `slow mornings` | 活动或可靠的时间信息 |
| 转场 | MVP 仅硬切；V3-3 才加 0.5 秒溶解 | 复用验证过的能力 |
| 镜头节奏 | 1.5–3 秒范围内按节拍切 | 2–3.5 秒范围内按节拍切 |
| 音乐 | MVP 固定一首 lofi 或 acoustic；V2-1 增加情绪对应曲目 | 复用已准备曲目 |

读取不到可靠时间或地点时，不生成看似精确的 `08:30 am · home`。使用能从素材支持的活动描述。

新增预设后，既要通过配置校验，也要实际渲染一段。只有 JSON 自检通过，不代表字体、颜色和转场最终正常。

<a id="s9"></a>

## 自然语言修改、缓存和撤销

<a id="s9-1"></a>

### 使用明确操作

正式结构以[`edit_request.json`：修改是受控操作，不是任意 JSON 补丁](timeline.md#s6-8)和机器 schema 为准。MVP 只开放 `set_title`、`set_warmth`、`remove_clip`，后端同时校验字段合法性和当前阶段能力。下例是解析后的删除请求；它还不是“渲染成功”的结果。

```json
{
  "schema_version": "1.0.0",
  "document_type": "edit_request",
  "project_id": "project_demo",
  "request_id": "request_remove_01",
  "base_version_id": "version_mvp_01",
  "instruction": "删掉有狗的那段",
  "resolution": {
    "decision": "ready",
    "operations": [
      {
        "type": "remove_clip",
        "clip_id": "clip_07"
      }
    ]
  }
}
```

前端可接受中英文修改要求，成片标题默认英文。生成成功摘要由后端根据实际完成的改动产生，不使用解析阶段的模型自报成功。

<a id="s9-2"></a>

### 哪些步骤需要重跑

| 修改 | 处理方式 |
| --- | --- |
| MVP：标题文字、暖度 | 保留选片；更新配置和覆盖图层，再渲染 |
| V2-3：关闭字幕 | 保留选片和音频；更新字幕开关再渲染 |
| V2：缩短时长、改变节奏 | 修改或重新生成计划，重新计算完整时间线，再渲染 |
| MVP：删除指定素材 | 删除对应镜头，记录排除约束，重算后续位置，再渲染；字幕和转场在相应阶段另验 |
| V2-1：更换音乐氛围 | 重新选择曲目，加载对应节拍，重算时间线，再渲染 |
| V3-1：改画幅 | 重算裁切和排版，再渲染；只有素材不适合新画幅时才需要重新选片 |
| V3-3：切换完整风格 | 纯视觉参数只重渲；若音乐或节奏变化，重算时间线 |

单纯删除将配置切换成 `duration_policy.mode=natural`，清除目标时长并记录排除素材。明确指定目标时长属于 V2-2，重新编排也不能把排除素材补回。多个候选时返回[`edit_request.json`：修改是受控操作，不是任意 JSON 补丁](timeline.md#s6-8)的 `needs_selection`，释放执行器，等用户确认后用新请求编号提交明确删除。

<a id="s9-3"></a>

### 按钮不用绕一次 AI

MVP 的 `Warmer` 固定按钮直接生成操作对象，自由输入才交给 `intent`；两者随后走相同校验与渲染流程。`20 sec` 按钮在 V2-2 才加入，`No subtitles` 在 V2-3 才加入；不要在 MVP 页面展示尚未实现的控制。

<a id="s9-4"></a>

### 缓存与版本

缓存按“原文件内容标识 + 分析配置/版本”区分；音乐缓存按“曲目 + 分析配置”区分。文件名相同不代表内容相同。

每次生成一个新版本，保存计划、最终时间线、配置快照、修改要求、摘要和成片。新版本通过检查后才成为当前版本；失败时继续保留旧视频。

撤销直接切回上一成功版本，不调用 AI、不重新渲染。撤销后再修改时创建新的唯一版本，并记录父版本；不要覆盖已经存在的 `v002`。

AI 输出校验失败可以最多修复重试 2 次，并设置总超时。首次生成持续失败时使用按时间排序、去重复的规则方案，并标注降级结果。修改请求持续失败时保留旧版本并说明未完成，不显示虚假的成功摘要。

<a id="s9-5"></a>

### V2-1：表达想要的感觉

MVP 验收通过后，优先支持两种明确、测试过的情绪预设，例如 `cozy_memory` 和 `bright_diary`。用户说 “Make it feel like a cozy memory”，`intent` 选择一个已定义的预设，再展开成允许的参数修改。

每个预设只组合已有能力。例如温暖回忆可以使用微暖色彩、较长的镜头和柔和的预选音乐；轻快日记可以使用明亮画面、较短镜头和轻快音乐。这些是需要观看验证的设计方案，不代表参数一改就必然产生相应感受。

若预设改变音乐或镜头节奏，必须重新计算时间线。生成摘要描述实际改动，例如 “Warmer colors, gentler music, longer shots”，让用户理解结果。没有实现这一层时，继续使用准确的 “Warmer” 等操作，不展示承诺过大的情绪按钮。
