## 现行产品方向（2026-10-10）

用户确定将 Vlogii 聚焦为生活类 Shorts：有贴画或艺术字的封面 → 几个镜头快速闪过 → 带基本字幕、少量短词/时间标注和轻特效的正文。完整作品是下一批设计方向，当前独立快剪与字幕不能视作整套风格已经完成。详见[结构与实现边界](shorts-direction.md)。现有保留比例、可选时长和倍速继续可用，不强制固定 30 秒。

下文保留原比赛的阶段方案与验收目标，其中“只生成 30 秒开场、无需语音、横屏”的描述是历史比赛范围；现行产品默认方向以上述用户决定为准，正式比赛验收尚未重新制定或完成。

## 产品定位：具体帮谁解决什么问题

<a id="s1-1"></a>

### 第一批用户

先服务喜欢杂志风、手账风生活记录，已经有拍摄习惯，但不愿花时间学习剪辑的大学生、留学生和日常记录者。先验证这一群体，再考虑扩大到“所有人”。

用户的典型情况是：手机里有早餐、通勤、上课、咖啡馆和夜晚的碎片，但一直没有整理成视频。

<a id="s1-2"></a>

### 产品承诺

- 自动挑选有代表性的瞬间，减少重复镜头，按活动与可确认的信息组织适合开场速剪的片段。
- 用人工设计的风格统一排版、色彩和节奏。
- 默认结果尽量接近可发布状态。
- MVP 用户可以说“删掉有狗的那段”“把标题改成 Slow Sunday”“暖一点”，并看到改动和撤销入口；缩短到指定时长放入 V2。

“有审美”既包括标题好看，也包括镜头选得合适、顺序合理、重要瞬间没有丢失。开发时间应同时投入视觉设计和内容组织。

<a id="s1-3"></a>

### 与现有产品的关系

CapCut 已经提供自动合并素材、音乐同步和风格化效果。因此，pitch 不再使用“CapCut 只提供工具和模板”的说法。[官方介绍](https://www.capcut.com/resource/capcut-autocut)

本项目要证明的是：**对这一类生活素材，我们能自动组织出更合适的内容，并让用户轻松表达具体修改。** 这是一项待验证的优势，不能仅靠架构图或参数数量证明。

<a id="s1-4"></a>

### 衡量是否有价值

优先记录三个问题：用户愿不愿发布、需要改几次、为什么不满意。赛后用同一份素材，对比本项目、按时间顺序拼接、CapCut AutoCut 的输出，让目标用户盲选。

“不修改就发布”的比例可作为长期指标；比赛阶段可以先记录“无需修改就愿意发布”的反馈，同时区分剪辑问题、素材问题和用户不愿公开的原因。

<a id="s1-5"></a>

### 针对 Adobe Creative 赛道的调整

截图中的关键表述是 “make something people feel”，并明确包含 design tools。本项目可以作为帮助普通人表达生活感受的创作工具参赛。

下面是根据赛道描述提出的展示建议，不是主办方公布的评分标准：

| 展示重点 | 项目如何体现 | 现场给出的证据 |
| --- | --- | --- |
| 情绪感受 | 音乐、镜头停留、色彩与标题共同表达一段生活的气氛 | 播放一支具有完整开头和收尾的短片 |
| 创作参与 | 用户决定想保留什么、希望怎样表达 | 用一句话修改，并展示结果 |
| 个人表达 | 选片和叙事来自用户自己的素材 | 展示原素材到成片的变化，保留有意义的瞬间 |
| 设计质量 | 字体层次、构图、节奏和界面形成统一风格 | 使用真实成片封面和大预览 |

MVP 验收通过后，V2 优先加入“同一份素材的两种情绪表达”，排序高于 V3 的更多导出比例。可以复用同一套布局和渲染代码，只改变少量已经实现的调色、音乐和节奏参数；不需要额外开发全新的风格引擎。

不要把“暖色”直接等同于“有情绪”。一个真实的笑容、一句原声、一段有呼吸感的停留，都可能比增加贴纸更有作用。测试时除是否愿意发布，再问一句：“这支片子有没有表达出你想记住的那一天？”

截图没有说明必须调用 Adobe API，也没有提供评分权重或参赛资格细则。是否要求 Adobe 产品集成，应以完整赛道规则为准；当前技术方案不自行增加这个前提。

## 分阶段交付：MVP 必达，V2 增强表达，V3 扩展能力

<a id="s2-1"></a>

### 阶段总览与进入条件

| 阶段 | 目的 | 是否属于 36 小时必达 | 进入条件 |
| --- | --- | --- | --- |
| MVP | 一组生活素材能够真正变成作品，并用一句话修改 | 是；单独完成这一阶段即可 Demo | 从这里开始，全部核心能力先完成 |
| V2 | 加强情绪表达与修改价值 | 否；有余力按下表顺序逐项加入 | MVP 在 Replit 完整验收通过，稳定版本已保留 |
| V3 | 扩展发布场景、风格和创作方式 | 否；以赛后为主 | V2 完成并稳定，再按顺序推进 |

**V2、V3 的功能不能成为 MVP 的隐性依赖。** 例如没有语音服务密钥，也必须能够生成 MVP 视频。后文保留的字幕、转场等设计均按阶段标记；出现冲突时，以本节交付范围为准。

<a id="s2-2"></a>

### MVP：比赛必须完成，能独立跑通 Demo

目标：**上传校园日常素材 → 自动生成约 30 秒杂志风开场速剪 → 一句话修改 → 撤销 → 下载。**

参考对象是校园 vlog 开头的速剪部分；后面的长片段只提供生活背景，不要求 MVP 生成完整长 vlog。选片验收看代表性瞬间、重复程度与音乐节奏，不要求在 30 秒里讲完一天的全部经过。

| 必做能力 | 明确边界 | 验收结果 |
| --- | --- | --- |
| 上传与素材展示 | 保存原件，读取时长和方向，生成缩略图；先以已验证的 1080p SDR 素材为主 | 能看到自己上传的素材；错误文件有提示 |
| AI 理解、选片与排序 | 一个主 AI 供应商；关键帧描述、减少重复、活动顺序、短标题 | 真实使用上传素材生成计划，且在第二套素材上也能出片 |
| 一种固定杂志风 | `magazine_scrapbook` 基础版：固定标题排版、微暖调色、少量固定装饰；无章节动画 | 输出的视频本身具有统一风格，页面封面来自真实成片 |
| BGM 与基础节拍剪辑 | 一首固定音乐，预先标好节拍；硬切，合理切点优先落在节拍上；原素材音轨静音 | 音乐可听、画面连续，无需 ASR、字幕或配音服务 |
| 固定输出 | 首次生成以 30 秒为目标，720p、30 fps、16:9、MP4 | 浏览器可以播放和下载；首次目标 30±1 秒；单纯删除后允许自然变短，见[JSON 数据契约：MVP 可用，V2/V3 可扩展](reference/timeline.md#s6) |
| 三类自然语言修改 | 改标题、调暖度、删除指定素材；不承诺任意剪辑指令 | 修改实际生效，并显示准确摘要；不支持的请求明确提示 |
| 版本与撤销 | 每次成功修改留一版；撤销返回上一成功版本 | 失败不覆盖旧成片，撤销不调用 AI 或重渲染 |
| 完整单页交互 | 上传、固定风格预览、大播放器、真实处理阶段、修改框、撤销、下载 | 页面没有假进度，也没有尚未实现的选项 |
| Replit 在线演示 | 单实例、串行任务；持久保存必要文件与 JSON | 正式链接能处理、播放、下载；重启后能读取已有成功版本 |

MVP 不运行语音转录，不保留口播，不做字幕或音乐压低。用户素材里可以有人声，但页面明确说明此阶段仅使用画面和 BGM。

**MVP 放行清单：**

- 一组真实素材从上传到生成、播放、下载全程跑通。
- 改标题、调暖度、删除素材分别成功一次，且没有误改其他内容。
- 修改失败仍能播放旧版本；撤销后能继续修改，不覆盖历史版本。
- 使用第二套素材复测；刷新页面及服务重启后能找到并播放已有成功版本。
- 在 Replit 正式环境彩排，并保留明确标记的备用成片与演示录屏。

上述任一项未通过，就继续修 MVP，不进入 V2。

<a id="s2-3"></a>

### V2：按顺序增加创意表达和编辑价值

一次只加入一项，接通、验收并保留稳定版本后，再开始下一项。比赛内可以只做到 V2-1，不要求凑齐整个阶段。

| 顺序 | 功能 | 为什么放在这里 | 最小实现与验收 |
| --- | --- | --- | --- |
| V2-1 | 同素材的第二种情绪表达 | 对 Adobe Creative 展示最直接，复用已有标题与调色能力 | 在相同布局上提供两组固定情绪参数，配两首预选音乐和不同镜头节奏；重算节拍，实际播放能感受到差异 |
| V2-2 | 缩短到指定时长 | 补齐常见修改需求，体现用户对内容的控制 | 在 30 秒视频上演示“缩到 20 秒”；先只开放 20/30 秒，不扩到 60 秒；保持排除约束和合法素材范围 |
| V2-3 | 一段短口播、字幕与 BGM 压低 | 保留个人声音有价值，但会引入转录和音画同步工作 | 只接一个 ASR，支持一段清晰短口播，整句保留、字幕对齐、音乐平滑降低；三项一起验收才开放 |

V2-1 是少量已有参数的组合，不新建第二套复杂排版引擎。V2-3 是一个完整功能包：只接通转录 API，但字幕或混音没做好，不算完成。Gemini / ElevenLabs 只有实际解决需求时才选用。

<a id="s2-4"></a>

### V3：按顺序扩展发布与创作能力

| 顺序 | 功能 | 增加的价值与边界 |
| --- | --- | --- |
| V3-1 | 9:16 竖屏导出 | 适配手机观看和分享；重新处理构图与文字布局，不能仅拉伸横屏成片 |
| V3-2 | 60 秒输出与更大素材集 | 支持更完整的一天；重新验证故事结构、处理耗时和资源限制 |
| V3-3 | 第二套完整风格与有限动画 | 加入 `clean_magazine`、章节标签、简单标题动画和一种溶解；逐项验证，避免一口气加入所有效果 |
| V3-4 | 自动抠图贴纸、可选一句旁白 | 个性化装饰优先，再考虑用户确认文本的一句旁白；不能影响主要内容和真实原声 |
| V3-5 | 一句话开始、参考图辅助配风格 | 在成熟的预设和参数范围内选择组合，不承诺任意参考图完美复刻 |

账号、多人协作、移动 App、复杂拖拽时间线、长口播去口误、大规模生产部署仍不进入这三个阶段。增加服务或赞助商数量本身不算功能目标。

<a id="s2-5"></a>

### 输入边界与速度目标

MVP 先用 10–15 段、总时长不超过 3 分钟的已验证素材验收，输出目标为 30 秒；三个小镜头只用于早期联调。素材必须有足够可用区间，不能靠大量复制凑时长。15–30 段素材与 60 秒输出的更大规模测试归 V3-2。

MVP 先验证 1080p SDR、横竖混合和旋转信息；HEVC、HDR 只有单独验证后才宣称支持。MVP 默认完整显示素材并用背景补空白；素材不足时明确失败，不复制凑时长，详见[JSON 数据契约：MVP 可用，V2/V3 可扩展](reference/timeline.md#s6)。上传体积上限和真实样片视觉效果仍需在运行环境中确定。

“90 秒出片”是优化挑战，**不是 MVP 放行门槛**。测量口径为上传完成后到成片可播放；另记上传和首次启动耗时。已缓存结果不能冒充首次生成速度。先达到稳定、观感合格、修改正确，再优化。

阶段范围与 JSON 数据契约已分别写入[分阶段交付：MVP 必达，V2 增强表达，V3 扩展能力](product.md#s2)、[JSON 数据契约：MVP 可用，V2/V3 可扩展](reference/timeline.md#s6)；歧义选择的数据状态也已定义。这些是原比赛设计；Vlogii 使用独立模型，并未完整适配。部署验证、比赛时长/风格和其他差距按功能对照逐项落实。
